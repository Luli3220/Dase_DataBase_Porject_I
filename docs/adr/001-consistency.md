# 001：事务与发布恢复

## 背景

问卷创建、草稿派生、统一保存和答卷提交涉及多个文档。首次成功提交还需设置 hasSubmissions，确定重复填写策略已经锁定；它也可能与关闭或发布同时发生。

## 选择

系统使用 MongoDB 副本集的 snapshot/majority 事务。提交、策略修改、关闭和发布共同写入 surveys 文档，通过 writeRevision 协调并发；冲突请求重新读取状态后执行。

草稿 revision CAS 校验当前编辑版本。统一保存将元信息、草稿和来源权限检查中的锁写入放在同一事务内，使编辑器的一次保存对应一次整体提交。

发布采用两步：先按 revision 冻结内容，再切换公开指针。冻结后中断时，draftVersion 仍指向该 sealed 版本，原公开版本继续服务；沿用同一 revision 重试完成发布。故障注入测试覆盖这一恢复路径。

## 影响

运行环境需要副本集，同一问卷的并发写入会在共享文档上形成竞争。当前采用单节点副本集演示，后续可根据数据规模评估写热点、缓存和聚合方式。

题目和选项 ID 与固定版本共同解释历史答案。题意变化通过新版本或新身份表达，已发布快照保留原内容。字段和流程见[数据库设计](../database-design.md)及[系统设计](../system-design.md)。
