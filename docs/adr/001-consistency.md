# 设计决策：事务与发布恢复

系统采用MongoDB单节点副本集，使用snapshot/majority事务处理问卷创建、草稿派生、答卷写入和重复策略锁定。

这些操作涉及多个文档。例如，首次成功提交需要同时保存答卷并设置hasSubmissions，以确定重复策略已经锁定；提交也可能与关闭或发布新版本并发发生。相关操作共同更新surveys.writeRevision，使冲突请求能够重新读取状态后执行。

发布分为两步：先按revision冻结版本，再切换surveys的公开指针。若冻结后中断，draftVersion保留对sealed版本的引用，原公开版本继续服务；相同revision再次发布即可完成恢复。该过程由故障注入测试验证。

这一选择将部署要求明确为副本集，同时使同一问卷的写入在共享文档上产生竞争。当前实现面向课程规模，后续数据量增长时可进一步评估写热点和统计方式。单文档CAS负责草稿编辑，事务负责跨文档的一致性。

题目和选项ID用于解释历史答案。题意或选项含义根本变化时应创建新ID，原发布版本继续保留。
