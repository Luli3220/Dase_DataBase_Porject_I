# 2026-10-27：保存、分页与统计说明

基线：已推送的 `72616496fc6cb143d71f93312bc46696487cc44e`，分支 `project2/question-library`。本次围绕原子保存、归档分页和统计口径展开，沿用七集合、固定版本和问卷快照。

## 实现调整

1. **原子保存**：新增 `SurveySaveInput` 和 `POST /api/surveys/{id}/save`，请求 `{metadata: SurveyPatch, draft: DraftInput}`，成功返回 `{survey,draft}`。将原SurveyService的元信息与草稿写入逻辑抽出事务内方法，旧接口与新接口共用，不嵌套事务；expectedRevision、来源校验、所有者、CSRF/Origin、重复策略锁保持。新接口任何步骤失败，metadata、草稿、来源权限锁写入一起回滚。旧PATCH和PUT各自行为保留。
2. **编辑器**：可编辑草稿采用统一保存；无草稿/冻结草稿的元信息单独保存沿用PATCH。等待成功后确认revision；保存中避免重复操作，冲突不清空输入、不继续预览或发布。明确4xx拒绝提示本次未生效；网络/不确定响应提示结果未确认，便于用户核对后重试。
3. **归档过滤**：GET questions新增 `activeOnly=false`，默认兼容。true在MongoDB初始match增加archived=false，先过滤再搜索、排序、分页及total；选择器传true，不再对分页结果过滤。普通管理页仍查看归档。题库成员available语义保持。
4. **统计口径**：检查后保留原聚合，surveyCount是授权及小样本抑制后，存在当前mode和精确题目版本所选提交的去重surveyId数。使用但无提交=0；latest_only旧答卷全部被新版替代=0；保留答卷跳过目标题，surveyCount仍可为1、answeredCount=0；多次提交按同surveyId只计1。usage.total是可见问卷版本引用条数，可能含同一问卷多版本，不能当成surveyCount。

代码变更限于 `models/domain.py`、`api/routes.py`、`api/question_routes.py`、`services/surveys.py`、`services/questions.py`、`static/app.js`，统计服务只补充两行口径注释。API、OpenAPI、技术说明和报告在本轮一并更新。
