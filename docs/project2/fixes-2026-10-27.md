# 保存、分页与统计说明修正

2026-10-27，在首轮提交 `7261649` 的基础上，进一步检查了编辑器保存、归档题目分页和统计数量的解释，并完成相应修改。

## 问题与修改

### 统一保存问卷

原编辑器分别保存问卷元信息和草稿，后一步失败时可能留下部分更新。新增 `POST /api/surveys/{id}/save`，接收 `{metadata: SurveyPatch, draft: DraftInput}`，在同一事务中完成保存，返回 `{survey,draft}`。草稿修订、来源、权限和重复填写策略一并检查，任一步失败时整体回滚。

服务提取了共用的元信息和草稿处理方法，原 PATCH 与 PUT 接口继续用于单独编辑。页面等待服务器确认后显示成功；冲突时保留输入，预览和发布等待保存成功。网络响应不确定时，提示用户核对状态后重试。

### 归档过滤先于分页

原选择器取得分页结果后再过滤归档题，可能导致页面数量与总数不一致。题目列表新增 `activeOnly`，默认 false；设为 true 时，MongoDB 先过滤归档题，再搜索、排序、分页和计数。选择器使用 true，管理页继续显示全部题目。

### 明确统计数量

统计保留原聚合逻辑，补充以下含义及边界说明：

- `surveyCount`：授权和样本筛选后，有本次所选提交的去重问卷数。同卷多次提交计为一份问卷。
- `submissionCount`：选中的提交次数；`answeredCount`：其中实际回答目标题的次数。
- 无提交，或旧版答卷全部被新版替代时，目标版本的有效统计问卷数为零。
- 答卷跳过目标题时，仍可计入问卷数和提交次数，实际回答数为零。
- `usage.total` 按可见问卷版本的引用记录计数，一份问卷可有多条记录。

修改涉及请求模型、问卷与题目服务、相关路由和编辑器，文件入口见[变更记录](change-log.md)。

|步骤与输入|预期结果及检查|

|两份问卷引用题目，但无提交；随后向其中一份提交两次|使用记录为 2 条，统计问卷数由 0 变为 1，原始提交数为 2|
|通过前题直接结束，跳过目标题|surveyCount=1、submissionCount=1、answeredCount=0、mean=null|
|同一人的旧答卷被新版本提交替代|目标旧版的有效口径为 0，历史原始口径保留原提交|
|浏览器保存冲突后尝试预览|调用统一保存，保留输入和按钮状态；保存成功后才进入预览|
|浏览器选择含归档题的分页，再返回管理页|选题分页为 10＋3，管理页可查看全部 23 题及归档状态|
